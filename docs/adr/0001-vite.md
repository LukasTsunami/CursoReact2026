# ADR 0001: Usar Vite como build tool e dev server

## Status

Accepted

## Contexto

O projeto é uma aplicação didática de React + TypeScript, estruturada em
fases (`fase-0` até `fase-9`), cada uma copiando a fase anterior e aplicando
só o diff de uma aula. Isso exige um dev server que dê feedback instantâneo
em sala de aula — o professor muda um arquivo e o resultado precisa
aparecer na tela quase imediatamente, sem quebrar o ritmo da explicação.

O time avaliou três alternativas:

- **Create React App**: descontinuado oficialmente, e o build já era lento
  mesmo antes disso.
- **Webpack manual**: configuração pesada demais para o tempo disponível de
  uma aula — o objetivo é ensinar React, não configuração de bundler.
- **Next.js**: traz SSR e um sistema de roteamento próprio embutido, o que
  conflita com o objetivo pedagógico de ensinar React Router isoladamente
  na aula 4 (fase-8).

## Decisão

Usar **Vite** como build tool e dev server em todas as fases do projeto.

Motivos principais:

- Dev server instantâneo (baseado em esbuild) e HMR (Hot Module Replacement)
  rápido — essencial para demonstrar mudanças ao vivo em sala.
- Configuração mínima para o par React + TypeScript.
- Suporte nativo a `import.meta.env`, usado para ligar/desligar o MSW
  conforme o ambiente.

## Consequências

- Cada fase do curso pode ser rodada com `npm install && npm run dev` sem
  configuração adicional.
- O time de testes ganha de graça a integração com Vitest, que reaproveita
  a mesma configuração e engine do Vite (ver ADR/playbook de testes).
- O projeto fica sem SSR/SSG "de fábrica" — uma limitação aceita
  conscientemente, já que se trata de uma SPA (Single Page Application)
  didática, não de um produto com requisitos de SEO.
- Alunos que só conhecem Create React App ou Webpack precisam de uma
  pequena reorientação (variáveis de ambiente com prefixo `VITE_`,
  `index.html` na raiz em vez de dentro de `public/`, etc.), coberta no
  playbook.

## Quando reconsiderar

- Se o projeto precisasse de SSR/SSG por requisitos de SEO ou de
  performance de carregamento inicial — isso está fora do escopo de uma
  SPA didática como esta, e apontaria para migrar para algo como Next.js.
